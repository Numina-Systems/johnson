# Human Test Plan: TUI UX Fix

## Prerequisites
- TS backend builds successfully: `bun run build` from project root
- Go TUI builds successfully: `go build -o ../bin/constellation-tui ./cmd/constellation-tui/` from `tui/`
- All automated tests pass: `go test ./...` from `tui/` and `bun test` from project root
- Terminal with at least 120x40 dimensions recommended

## Phase 1: Startup and Session Creation

| Step | Action | Expected |
|------|--------|----------|
| 1.1 | Run `just dev` in a terminal | TUI launches directly into the Chat screen with an empty conversation. The input textarea is focused at the bottom. Status pane shows "Ready". |
| 1.2 | Type `/sessions` and press Enter | Screen navigates to Sessions list. The session created at startup appears at the top of the list (either with an auto-generated title or truncated session ID). |
| 1.3 | Stop the TS backend process (e.g., kill `bun` or make `src/index.ts` unreachable), then run `just dev` | TUI opens on the Sessions list, not a blank chat. Check stderr for "warning: failed to create initial session". |

## Phase 2: Slash Command Navigation

| Step | Action | Expected |
|------|--------|----------|
| 2.1 | From Chat, type `/tools` and press Enter | Screen navigates to Tools screen. |
| 2.2 | Type `/back` and press Enter (or press Escape) | Returns to Chat screen. |
| 2.3 | Type `/secrets` and press Enter | Screen navigates to Secrets screen. |
| 2.4 | Press Escape | Returns to Chat screen. |
| 2.5 | Type `/schedules` and press Enter | Screen navigates to Schedules screen. |
| 2.6 | Press Escape | Returns to Chat screen. |
| 2.7 | Type `/prompt` and press Enter | Screen navigates to System Prompt screen. |
| 2.8 | Press Escape | Returns to Chat screen. |
| 2.9 | Type `/to` in the input (do NOT press Enter) | Screen remains on Chat. No navigation occurs. |
| 2.10 | Complete typing to `/tools` (still no Enter) | Screen still remains on Chat. |
| 2.11 | Press Enter | Screen navigates to Tools. |
| 2.12 | Press Escape back to Chat. Type `/new` and press Enter | Chat screen resets with a new empty session. The input remains focused. Previous messages are cleared. |
| 2.13 | Type `/quit` and press Enter | TUI exits cleanly. |

## Phase 3: Stack Navigation

| Step | Action | Expected |
|------|--------|----------|
| 3.1 | Launch TUI. From Chat, go to `/sessions`, then `/tools` | Stack is Chat -> Sessions -> Tools. |
| 3.2 | Press Escape | Returns to Sessions screen. |
| 3.3 | Press Escape | Returns to Chat screen. |
| 3.4 | Press Escape on Chat (root of stack) | Nothing happens. Screen stays on Chat. |
| 3.5 | Go to `/sessions`. Use arrow keys to select a session and press Enter | Chat screen loads with the selected session's messages. Sessions screen is popped from the stack. |

## Phase 4: Session List Rendering

| Step | Action | Expected |
|------|--------|----------|
| 4.1 | Navigate to `/sessions` with multiple sessions | Each session occupies exactly one line. No blank rows between items. |
| 4.2 | Arrow up/down through the list | Selected session has a `▸` prefix and a visually distinct background colour. The highlight follows the cursor. Unselected sessions have a space prefix. |
| 4.3 | Create a session without sending any messages (it won't get a title) | The untitled session appears as "session XXXXXX..." with a truncated ID. |
| 4.4 | Start typing in the session list filter (if available) | Filtering narrows the list based on session titles. |
| 4.5 | Use a fresh data directory so no sessions exist, navigate to `/sessions` | An empty state message is displayed (Bubble Tea's default). |

## Phase 5: Error Visibility

| Step | Action | Expected |
|------|--------|----------|
| 5.1 | Open a session. Kill the backend process while the TUI is running | The status pane shows an error message. The crash recovery screen appears with "Press 'r' to restart" and "'q' to quit". |
| 5.2 | Press 'r' | Backend restarts. TUI recovers to a usable state. |
| 5.3 | If a message load fails (e.g., corrupt session), observe the status pane | Status pane shows "Error: [error details]" in a visually distinct (red) style. |
| 5.4 | After an error, type a message and press Enter | The message sends successfully. The textarea clears. The error state does not block input. |

## Phase 6: Existing Behaviour Preserved

| Step | Action | Expected |
|------|--------|----------|
| 6.1 | On the Chat screen, observe the layout | Three distinct zones: message viewport (top), status pane (middle), input textarea (bottom). |
| 6.2 | Send "list three items with bullet points" | Agent response renders with formatted markdown (bullets, bold, code blocks via glamour), not raw markdown syntax. |
| 6.3 | Send a message that triggers tool use (e.g., "what time is it?") | Status pane updates in real-time: "Thinking..." -> "Running code..." -> token/round stats on completion. |
| 6.4 | Open a session with 50+ messages. Scroll up to the top | Older messages load automatically above existing content. No duplicates. No messages lost. |

## End-to-End: Full Session Lifecycle

1. Run `just dev`. Confirm Chat screen with empty session.
2. Send "hello" and wait for agent response. Confirm response appears in viewport with markdown rendering.
3. Type `/new` and press Enter. Confirm a fresh empty chat replaces the previous one.
4. Send "what is 2+2?" and wait for response.
5. Type `/sessions` and press Enter. Confirm both sessions appear in the list.
6. Select the first session. Confirm it loads with the "hello" conversation.
7. Type `/tools` and press Enter. Confirm Tools screen loads.
8. Type `/secrets` and press Enter. Confirm Secrets screen pushes on top.
9. Press Escape twice. Confirm stack unwinds back to Chat.
10. Ctrl+C to quit. Confirm clean exit.

## End-to-End: Multi-Instance Independence

1. Open three terminal tabs.
2. Run `just dev` in each tab within 2-3 seconds.
3. In each tab, type `/sessions` and press Enter.
4. Confirm each tab shows a different session at the top of the list.
