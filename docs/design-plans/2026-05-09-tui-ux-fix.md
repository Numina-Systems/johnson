# TUI UX Fix Design

## Summary

The Go Bubble Tea TUI currently has several friction points that make it feel unpolished: it opens to a session picker instead of dropping straight into a conversation, uses hardcoded back-navigation that always returns to the session list rather than the previous screen, renders lists with unnecessary vertical padding, and silently discards RPC errors. This design plan addresses all four issues as targeted, scoped fixes — no architectural changes, no new abstractions beyond a single custom list delegate.

The approach is additive patching rather than redesign. The startup flow gains a `session/create` call before the app model initialises, so the user lands directly in a fresh chat. The existing `backToSessionsMsg` navigation message is replaced with a generic `popScreenMsg` that respects a proper screen stack, unlocking correct back-navigation from any depth. List density is fixed with a `SetSpacing(0)` configuration for most screens and a compact single-line `ItemDelegate` for sessions. Error visibility gets a new `messagesErrorMsg` type that surfaces failures in the status pane without blocking further interaction. All existing behaviour — hybrid chat layout, glamour markdown rendering, streaming events, cursor-based pagination — is preserved unchanged.

## Definition of Done

The Go Bubble Tea TUI launches directly into a new chat session (no session picker on startup), routes slash commands from the chat input for screen navigation (`/sessions`, `/tools`, `/secrets`, `/schedules`, `/prompt`, `/back`, `/quit`), uses full-screen transitions between all screens with stack-based back-navigation, renders session lists with compact item density, and surfaces RPC errors visibly instead of swallowing them silently. All other behaviour from the original bubbletea-tui design (hybrid chat layout, glamour rendering, streaming events, cursor-based pagination) is preserved.

## Acceptance Criteria

### tui-ux-fix.AC1: TUI launches directly into a new chat session
- **tui-ux-fix.AC1.1 Success:** On launch, user sees the chat screen with an empty conversation and the input area focused — no session list shown
- **tui-ux-fix.AC1.2 Success:** The new session appears in the session list when navigating to `/sessions` after launch
- **tui-ux-fix.AC1.3 Failure:** If `session/create` RPC fails on startup, TUI falls back to session list with visible error message
- **tui-ux-fix.AC1.4 Edge:** Multiple rapid launches each create independent sessions (no session reuse)

### tui-ux-fix.AC2: Slash commands route to correct screens
- **tui-ux-fix.AC2.1 Success:** `/sessions`, `/tools`, `/secrets`, `/schedules`, `/prompt` each navigate to their respective full-screen views
- **tui-ux-fix.AC2.2 Success:** `/back` and `/quit` pop the screen stack and exit the TUI respectively
- **tui-ux-fix.AC2.3 Success:** `/new` creates a fresh session and replaces the current chat without pushing onto the stack
- **tui-ux-fix.AC2.4 Failure:** Unknown slash commands (e.g., `/foo`) are silently ignored — no crash or error
- **tui-ux-fix.AC2.5 Edge:** Slash commands only trigger on Enter, not while typing (partial `/to` doesn't navigate)

### tui-ux-fix.AC3: Stack-based back-navigation works correctly
- **tui-ux-fix.AC3.1 Success:** Escape from any non-chat screen returns to the previous screen in the stack (not always sessions)
- **tui-ux-fix.AC3.2 Success:** Selecting a session from `/sessions` replaces the current chat and pops the sessions screen
- **tui-ux-fix.AC3.3 Success:** After `/new`, escape from chat behaves the same as the original chat (no orphaned stack entries)
- **tui-ux-fix.AC3.4 Edge:** Deep stack (`Chat → Sessions → Tools`) unwinds correctly: escape from Tools → Sessions, escape from Sessions → Chat

### tui-ux-fix.AC4: Session list renders with compact item density
- **tui-ux-fix.AC4.1 Success:** Each session occupies exactly one line with title and metadata inline
- **tui-ux-fix.AC4.2 Success:** Selected session has visual highlight (background colour and `▸` prefix)
- **tui-ux-fix.AC4.3 Success:** Untitled sessions display truncated session ID
- **tui-ux-fix.AC4.4 Success:** List filtering/search works on session titles
- **tui-ux-fix.AC4.5 Edge:** Session list with 0 items shows empty state message

### tui-ux-fix.AC5: RPC errors are visible
- **tui-ux-fix.AC5.1 Success:** Failed message load on chat entry shows error in status pane with red styling
- **tui-ux-fix.AC5.2 Success:** User can still type and send messages after a load error
- **tui-ux-fix.AC5.3 Failure:** Failed older-message pagination shows error without losing already-loaded messages

### tui-ux-fix.AC6: Existing behaviour preserved
- **tui-ux-fix.AC6.1 Success:** Chat hybrid layout (viewport + status + input) renders correctly
- **tui-ux-fix.AC6.2 Success:** Agent responses render as formatted markdown via glamour
- **tui-ux-fix.AC6.3 Success:** Streaming events update status pane in real-time during agent processing
- **tui-ux-fix.AC6.4 Success:** Cursor-based pagination loads older messages on scroll-up

## Glossary

- **Bubble Tea**: A Go framework for building terminal user interfaces using an Elm-inspired model-update-view architecture. Each screen is a `tea.Model` with `Init`, `Update`, and `View` methods.
- **JSON-RPC 2.0**: A lightweight remote procedure call protocol over line-delimited JSON. The Go TUI communicates with the TypeScript backend exclusively through this protocol via stdin/stdout.
- **Screen stack**: A slice of screen identifiers the app model maintains to support nested navigation. Pushing a screen navigates forward; popping returns to the previous screen.
- **`popScreenMsg`**: The new generic navigation message type introduced by this design to replace `backToSessionsMsg`. Tells the app model to pop the current screen off the stack.
- **`backToSessionsMsg`**: The existing navigation message that hardcodes returning to the sessions screen on escape — the specific behaviour this design replaces.
- **`ItemDelegate`**: A Bubble Tea list interface that controls how individual list items render, and reports their height and spacing. The session list gets a custom implementation; other lists use the built-in `DefaultDelegate`.
- **`DefaultDelegate`**: The built-in Bubble Tea list item renderer. Supports configurable spacing via `SetSpacing(0)`, used to compact tool, schedule, and other non-session lists.
- **lipgloss**: A Go library for terminal text styling (colours, padding, alignment). Used for rendering the compact session delegate's title and metadata.
- **glamour**: A Go library that renders Markdown as styled terminal output. Used for agent response rendering in the chat view.
- **Cursor-based pagination**: A pagination strategy that uses an opaque cursor rather than page numbers, enabling stable pagination over a changing dataset.
- **`messagesErrorMsg`**: The new message type introduced to surface RPC failures during message loading. Displayed in the status pane with red styling without blocking further interaction.
- **Status pane**: The middle section of the hybrid chat layout that shows agent status events and, after this change, load errors.
- **Zellij**: A terminal multiplexer. Conflict source for `ctrl+` keybindings — reason for removing them in favour of slash commands.

## Architecture

Four targeted fixes to the existing Go Bubble Tea TUI, plus a session list polish pass. No architectural changes — the existing screen model, slash command routing, JSON-RPC protocol, and hybrid chat layout are all preserved. Changes are scoped to startup flow, list rendering, error handling, and navigation stack behaviour.

### Startup Flow

`main.go` creates a new session via `session/create` RPC before initialising the app model. The session ID is passed to `NewAppModel`, which sets `activeScreen: ScreenChat` and creates a `ChatModel` for that session. The screen stack starts as `[ScreenChat]`.

If the `session/create` call fails, fall back to `ScreenSessions` with an error banner so the user can retry or pick an existing session.

### Navigation Stack

All screens emit a generic `popScreenMsg` on escape instead of the current `backToSessionsMsg`. The app model handles `popScreenMsg` by calling `m.popScreen()`, returning to whatever screen was previous in the stack.

Stack behaviour:
- Launch: `[Chat]`
- `/sessions` from chat: `[Chat, Sessions]` — escape returns to Chat
- `/tools` from chat: `[Chat, Tools]` — escape returns to Chat
- `/new` from chat: `[Chat]` with new session replacing old (no stack push)
- Select session from `/sessions`: `[Chat]` with selected session replacing old, sessions screen popped

The `/new` slash command creates a session via RPC and replaces the current chat model at the bottom of the stack. It does not push a new screen.

### Session List Delegate

A custom compact delegate renders each session on a single line:

```
▸ email-digest                    62 msgs · 10 min ago
  live-news-briefing              12 msgs · 22h ago
  daily-meeting-rundown            4 msgs · yesterday
```

Title left-aligned, metadata right-aligned and dimmed. Selected item gets highlight background and `▸` prefix. Untitled sessions show truncated session ID (e.g., `session 2af671...`). Implements `ItemDelegate` with `Height() = 1`, `Spacing() = 0`. Filter via `FilterValue()` returns the title.

### List Density for Other Screens

All non-session lists (tools, secrets, schedules) configure `DefaultDelegate` with `SetSpacing(0)`. Descriptions remain visible where they exist (skills, builtins). No custom delegate needed — just the spacing configuration.

### Error Visibility

Chat `Init()` surfaces RPC errors via a new `messagesErrorMsg` type instead of returning empty messages silently. The error displays in the status pane with red styling. The user can still type and send messages — the error is informational, not blocking.

Startup session creation failure falls back to the session list with an error banner. Other screens (tools, secrets, schedules) already handle errors correctly.

## Existing Patterns

The existing Go TUI follows Bubble Tea conventions: screen-specific models implementing `tea.Model`, message types for async results, `tea.Cmd` functions for RPC calls. This design follows those patterns exactly.

Slash command routing is already implemented via `SlashCommandMsg` in `tui/internal/app/app.go` (lines 142-166) and interception in `tui/internal/app/chat.go` (lines 224-230). The `/new` command follows the same pattern — new case in the `SlashCommandMsg` switch.

The `backToSessionsMsg` type is the only navigation message that bypasses the stack. Replacing it with `popScreenMsg` aligns with the existing `popScreen()` method in the app model.

The custom session delegate follows the same `ItemDelegate` interface that `DefaultDelegate` implements — `Render`, `Height`, `Spacing`, `Update`. No new abstractions.

## Additional Considerations

**Existing ctrl+ keybindings:** The current `app.go` still has `ctrl+t`, `ctrl+s`, `ctrl+d`, `ctrl+p` handlers alongside the slash command routing. These should be removed in Phase 1 to avoid confusion and Zellij conflicts. Slash commands are the sole navigation mechanism.

**Session title display:** The compact delegate shows session titles, but many sessions may be untitled (auto-created on startup). The `maybeGenerateSessionTitle()` function in the backend already auto-titles sessions after the first chat exchange, so most sessions will have titles by the time the user visits `/sessions`.
